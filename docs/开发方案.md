# Q6 Pro Host LED V1 开发规格

状态：设计基线，分阶段实现。2026-10-02。

## 范围与职责

独立于 Smial；Windows 使用 .NET 10/C#，V1 无 GUI、托盘、插件、动画或 Delta。
Windows 解析 JSON、获取状态、结算规则，再把坐标、覆盖标记和 RGB 编码为 HID 二进制。
固件不解析 JSON、名称、Rule ID、状态类型或匹配规则；复用 Keychron 的扫描、蓝牙、VIA、旋钮和 RGB 驱动。
第一版仅通过 USB 控制，固件新增的 Host 状态全部保存在 RAM，不写 EEPROM。

## 显示语义

一个规则可控制任意多个带 LED 的位置。黑色覆盖表示强制熄灭；解除覆盖表示恢复底层 RGB。
Host 覆盖服从 RGB 总开关和当前亮度；关闭 RGB 不清除 active。
软件正常退出、崩溃和 HID 断开后，固件保留最后成功提交的状态，不设显示心跳超时。
断电/固件重启清空 RAM；连接、重连和恢复时软件强制重新同步完整状态。
休眠期间服从键盘电源管理，不主动唤醒灯光；恢复后重新绘制。

## 规则优先级（已确认）

仅“不匹配 → 匹配”计为触发。软件串行处理事件，最新触发者优先。
同一批结算内同时触发，creationOrder 最大（最新创建）的规则优先。
creationOrder 为持久化正整数，全配置唯一；不得以 JSON 数组位置替代。
已有规则修改保留创建顺序；新建使用历史最大序号之后的序号，nextCreationOrder 保留高水位。
优先规则失效后重新结算剩余活动规则。重复状态通知不改变触发顺序。
获胜规则 override=false 强制解除覆盖，不直接回退到低优先级规则；该规则失效后才回退。
热重载时 id、creationOrder、source、match 不变的规则保留激活次序；仅颜色改变不重新触发。
匹配条件改变的规则重新评价为新触发；新增同时活动规则按创建顺序排序。
初始读取的各 Provider 状态作为同一批结算，不能依赖回调抵达速度决定初始优先级。

## 配置与命令

version=1；完整配置包含 nextCreationOrder 和 rules。Rule 包含 id、name、creationOrder、source、match、display。
V1 source.type=windows.audio.defaultPlayback，source.role=multimedia；以 match.endpointId 精确比较音频设备 ID。
display 各项含 row、column、override、color。color 固定为 #RRGGBB；解除覆盖时仍要求合法颜色但不使用。
禁止未知字段、重复 JSON 属性、重复 Rule ID/创建序号、同规则重复坐标、不存在的 LED 和越界坐标。
校验离线执行，不打开 HID；错误输出路径，JSON 解析错误同时报告可用的行列信息。
validate 检测语法和语义；config-set 从一份完整 JSON 更新目标文件，先校验后原子替换。
config-set 保留同 ID 的创建序号，禁止重用旧创建序号；不进行隐式类型转换或大小写匹配。
后续增加专门的新建/删除规则命令时，也遵守 nextCreationOrder 高水位。
热重载采用去抖，读取与校验全部成功后替换；失败保留旧配置。Provider 初始化也必须成功后才切换。

## 音频状态

Core Audio 监听 multimedia 默认播放设备，而非 SoundSwitch 进程或按键。
Endpoint ID 由设备列举命令提供，不猜测用户设备 ID。实际切换仍由 SoundSwitch/Windows 完成。
明确无默认设备属于 Known(null)，取消对应匹配；查询异常属于 Unknown，保留最近 Known。
首次 Unknown 没有历史值时，该来源规则不激活；初次快照可为空。
先订阅并缓冲通知，再读取初值，并串行协调通知与读取结果，避免启动漏事件。
示例提供音响/耳机两规则，各自同时设置 F13/F14：选中白色，未选中黑色。示例 ID 必须替换后才能代表真实设备。

## 全量稀疏快照

每次从所有活动规则重新计算完整结果，不基于旧 HID Delta 累积。
结算完成后移除 override=false 项，剩余项按 row、column 排序形成唯一快照。
staging 在新事务开始时全部解除覆盖；快照缺失的位置在提交后恢复底层 RGB。
零项快照用于清除全部覆盖。V1 不额外实现 RELEASE_ALL 或 DELTA_UPDATE。
软件区分 Desired、最后确认 Applied 和待同步标志。发送失败即使 Desired 不变也继续退避重试。
一次只执行一个事务；状态快速变化时合并为最新 Desired，不无限排队旧快照。

## 固件事务与渲染

active/staging 双缓冲按实际 RGB LED index 保存 override、r、g、b。
校验行列界限、matrix_co、NO_LED、LED 数量。实际 RAM 使用以编译产物为准。
GET_INFO、BEGIN、DATA、COMMIT、STATUS 的线协议在 docs/protocol.md 冻结后才实现硬件发送。
重复 DATA 必须内容完全一致，不累计项数；内容不同拒绝事务；跨包重复坐标拒绝事务。
相同 BEGIN 重试不清空 staging；新事务可取代未提交事务，旧事务包被拒绝。
COMMIT 幂等；固件保留最近已提交事务身份，ACK 丢失后可查询确认。
事务需会话身份，防止 Agent 重启后计数复用；断电通过重新握手和强制全量恢复。
staging 无进展 5 秒超时丢弃（不影响 active）；Host 最多恢复 3 次，随后重新握手/全量重试并退避。
32 字节报告，不用 raw_hid_receive 替换 VIA。入口与命令空间必须核对本地实际 fork。
完整批次只在 RGB 帧安全边界切换；APPLIED 表示新 active 已在该边界启用，不表示物理 LED 已完成刷新。

## 实施阶段

1. 文档、可构建的 Windows 项目、配置校验/设置、规则结算、离线预览及自动测试。
2. 固件原样构建基线，核对路由；冻结字节级协议，实现 GET_INFO 和 HID 诊断。

## 必测场景

规则触发顺序/同时触发/重复通知/回退/强制解除/配置修改；黑色不等于解除。
JSON 半写入、未知字段、重复字段/规则/创建序号/坐标、无 LED 位置。
空快照、乱序包、重复包异内容、缺包、错误事务、ACK 丢失、重启会话、超时和重连。
发送失败但 Desired 不变时仍恢复；发送中状态变化最终收敛。
RGB 总开关/亮度/休眠、全键多包原子显示、SoundSwitch 和 Windows 手动切换音频。
